# Mini React Lab 발표 대본

> 괄호 안은 화면 조작 메모입니다. README의 접힌 설명은 질문이 나오면 펼칩니다.

## 0:00–0:25 · 소개

*(README 맨 위)*

안녕하세요. 저희가 만든 Mini React Lab은 화면이 바뀌는 과정을 직접 확인할 수 있는 학습 사이트입니다. 한 페이지에 제목을 편집하는 실습과 앱의 상태를 바꾸는 실습을 넣었습니다. 위쪽에서 바꾼 제목을 아래쪽 메모로 가져오면 두 실습을 이어서 볼 수 있습니다.

## 0:25–0:50 · 흐름도

*(흐름도에서 첫 요청과 두 갈래가 합쳐지는 부분을 짚기)*

서버가 파일을 보내면 브라우저에서 실습이 시작됩니다. 패치를 누르면 편집한 화면을 읽고, 플러스 삼을 누르면 바뀐 상태로 다음 화면을 만듭니다. 두 경로 모두 같은 디프와 패치를 거칩니다.

## 0:50–1:35 · 제목 변경과 Patch

*(첫 번째 캡처에서 오른쪽 테스트 영역, 왼쪽 실제 영역, 아래 명령을 차례로 짚기)*

첫 번째 캡처에서 오른쪽은 테스트 영역이고, 왼쪽은 실제로 적용한 결과입니다. 텍스트 변경을 눌렀을 때는 오른쪽 제목만 바뀌었습니다. 패치까지 적용하니 왼쪽 제목도 바뀌었고, 아래에 글자 바꾸기 한 건이 표시됐습니다.

패치를 누르면 오른쪽 화면을 다시 읽어 왼쪽의 마지막 적용본과 비교합니다. 이 경우에는 기존 제목의 글자만 고칩니다. 적용한 화면은 히스토리에 저장해 두 영역에서 되돌리거나 다시 적용할 수 있게 했습니다.

## 1:35–2:30 · 메모 복사와 상태 갱신

*(두 번째 캡처에서 메모와 숫자 3을 짚기)*

두 번째 캡처는 왼쪽 제목을 아래 메모로 복사하고 플러스 삼 묶기를 누른 결과입니다. 숫자는 삼으로 바뀌었고 메모에는 복사한 제목이 남아 있습니다. 여기서 위쪽의 되돌리기를 누르면 두 영역의 제목은 처음으로 돌아갑니다. 메모는 앱 상태에 따로 저장했기 때문에 복사해 둔 글자가 남습니다.

플러스 삼 묶기는 이전 값에 하나를 더하는 요청을 세 번 보냅니다. 저희는 이 요청을 모아 앞의 결과를 다음 계산에 넘기도록 했습니다. 그렇게 계산한 삼으로 다음 화면을 만들고, 앞에서 제목을 고칠 때 쓴 디프와 패치로 숫자를 한 번 반영합니다.

## 2:30–3:10 · 구독과 계산

*(README의 구독·계산 설명을 짚기)*

구독 실습에서는 에이를 듣다가 비로 바꾼 뒤, 다시 에이 신호를 보냈습니다. 받은 수가 그대로인 걸 보면 이전 연결이 끊긴 걸 확인할 수 있습니다. 이 연결을 유즈 이펙트로 관리했습니다.

계산 실습에서는 보기와 수량을 바꾸는 버튼을 따로 뒀습니다. 보기만 바꾸면 화면은 갱신되지만 수량이 같아서 유즈 메모가 이전 합계를 다시 씁니다. 수량을 올리면 새로 계산합니다.

## 3:10–3:45 · 실제 React와 비교

*(README의 React 비교 문단으로 이동)*

실제 리액트도 다음 화면을 계산해 필요한 부분을 실제 돔에 반영합니다. 저희는 편집한 돔을 비교에 쓸 수 있게 하고, 그 결과를 글자 바꾸기 같은 명령으로 화면에 표시했습니다. 실제 리액트에서는 자식 컴포넌트도 자기 상태를 가질 수 있습니다. 저희는 과제 조건에 맞춰 루트 앱에 상태를 모으고, 자식에게 필요한 값을 넘겼습니다. 두 실습에 같은 엔진을 썼습니다. 감사합니다.
